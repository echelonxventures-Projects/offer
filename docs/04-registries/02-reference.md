**204 entries**. Every one of them is an extension point:
registering an entry adds behaviour without changing any engine.

## Entries

### `acquisition-mode`


| Key | Label | Notes |
| --- | --- | --- |
| `automatic` | Applies automatically | No action by the subject. Promotions, cashback, commissions. |
| `code` | Code presented | A shared code everyone may use, or a unique code tied to a grant. Matched case- and whitespace-insensitively. |
| `earned` | Earned | Unlocked by meeting a condition, then held as a grant. Loyalty rewards. |
| `issued` | Issued in advance | Granted to a named subject before the interaction. Subsidies, employee benefits. |
| `referred` | Obtained by referral | Granted through another subject's referral. |

### `alert-rule`


| Key | Label | Notes |
| --- | --- | --- |
| `audit.unverified` | Audit chain verification failed | A stored record no longer matches its hash. Treat as a security incident, not a bug. |
| `funding.exhausted` | A campaign cannot be funded | Customers are being refused a price they may already have been shown. |
| `funding.utilisation` | Budget nearly exhausted |  |
| `ledger.unbalanced` | Ledger does not balance | Value has been created or destroyed. This should be impossible: unbalanced transactions are refused at the write boundary. |
| `reservations.stale` | Reservations are piling up | Budget is held by checkouts that were never captured or released. The sweep is probably not running. |
| `rules.broken` | A condition cannot be evaluated | Looks like a client error and is not: the offer silently delivers nothing until the condition is fixed. |
| `stacking.greedy` | Stacking is no longer optimal | More than ten offers were simultaneously eligible. Usually a campaign-portfolio problem, not an engineering one. |

### `attribution-model`

How credit divides across a journey.

| Key | Label | Notes |
| --- | --- | --- |
| `first_touch` | First touch | All credit to the touchpoint that started the journey. |
| `last_touch` | Last touch | All credit to the final touchpoint. The default nearly everywhere, and the crudest. |
| `linear` | Linear | Credit divided equally across every touchpoint. |
| `position_based` | Position based (40/20/40) | 40% first, 40% last, 20% divided among the middle. |
| `time_decay` | Time decay | Later touches weigh more, halving every step back through the journey. |

### `benefit-type`

How a benefit's value is computed.

| Key | Label | Notes |
| --- | --- | --- |
| `fixed_price` | Fix the price | Sets each targeted unit to a fixed price; the benefit is the difference. |
| `flat` | Flat amount | A fixed value, never more than the base it applies to. |
| `free_quantity` | Buy X get Y free | For every `buy` units bought across targeted lines, `free` units are free. The cheapest units are the free ones. |
| `item_grant` | Grant an item | Adds a product or service. The value is its declared cost, which is what funding settles. |
| `percentage` | Percentage of base | rate% of the targeted subtotal. Serves discounts, cashback, commissions alike. |
| `points_accrual` | Points per unit of spend | Earn `points` for every `per` whole units of the base. Output is denominated in the benefit's own unit. |
| `tiered` | Tiered by spend | Highest tier whose threshold the base meets. Tiers are [{ min, rate \| amount }]. |
| `volume` | Tiered by quantity | Same shape as 'tiered' but thresholds are item counts. Tiers are [{ minQuantity, rate \| amount }]. |

### `decision-objective`

What 'best' means when offers compete.

| Key | Label | Notes |
| --- | --- | --- |
| `max_applied` | Maximise number applied | Prefers stacking many small benefits. Mostly useful for testing stacking rules. |
| `max_payable_reduction` | Maximise immediate saving | Optimises what comes off the price now, ignoring deferred value. Right for conversion at checkout. |
| `max_priority` | Respect authored priority | Follows the priority numbers the campaign author set, ignoring computed value. |
| `max_subject_value` | Maximise subject value | The default. Gives the subject the most value expressed in the interaction's unit. |
| `min_cost` | Minimise cost | The cheapest combination that still applies something. Right when an incentive must be present but small. |

### `maintenance-job`


| Key | Label | Notes |
| --- | --- | --- |
| `audit.anchor` | Publish the audit head externally | Without an anchor, an attacker who can rewrite the whole chain can forge it consistently and verification will pass. |
| `audit.checkpoint` | Checkpoint the audit chain | Verify forward from the last checkpoint so verification does not become O(all of history). |

| `health.check` | Integrity health check | Ledger balance, audit verification, funding headroom, stale reservations. |
| `reservations.sweep` | Release stale reservations | Without this, an abandoned checkout holds budget forever and a campaign with money left starts refusing customers. The most important job here. |

## Capabilities

registries above, this list is deliberately closed: a new verb is a change to
the platform's contract with its callers, not a configuration change.

| `govern` | author | yes | no | Run policy review, or move an exchange through its lifecycle. |
| `validate` | author | no | no | Check an exchange against policy without changing it. |
| `discover` | distribute | no | no | What is available to this subject, here, now. |
